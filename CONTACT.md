# Contact Luastra

Choose the narrowest contact route for the subject. This helps private reports
reach the right workflow without moving ordinary project discussion out of the
public repository.

| Purpose | Contact |
|---|---|
| General project and public enquiries | `hello@luastra.dev` |
| Private user-support enquiries | `support@luastra.dev` |
| Suspected security vulnerabilities | `security@luastra.dev` |
| Privacy questions and data-subject requests | `privacy@luastra.dev` |
| Licensing, trademark, and other legal enquiries | `legal@luastra.dev` |

Use GitHub Issues for reproducible non-security defects and bounded feature
proposals, and GitHub Discussions for public usage and design questions. See
[`SUPPORT.md`](./SUPPORT.md) for the support boundary.

For a suspected vulnerability, prefer the private reporting route and follow
[`SECURITY.md`](./SECURITY.md). Never disclose a vulnerability, credential,
token, personal data, or private proof of concept in a public issue.

These addresses do not create a service-level, response-time, confidentiality,
legal-representation, or commercial-support commitment. Do not send secrets or
unrelated personal data by email.
